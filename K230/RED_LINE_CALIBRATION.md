# K230 红线巡线与新车头方向标定

> 本文记录必须在 K230、MSPM0 和实车上完成的验证。代码中的阈值与增益只是安全起始值，未经过本表记录前不得视为完成标定。

## 1. 新车体坐标约定

车头已经旋转 180°，全工程统一使用以下语义：

- 正速度：朝新车头前进，即原来的后退方向；
- 新逻辑左轮：原右轮硬件通道；
- 新逻辑右轮：原左轮硬件通道；
- K230 图像不镜像，图像右侧误差为正；
- 红线朝右前方延伸时方向角为正；
- 正转向修正使新逻辑左轮加速、新逻辑右轮减速，车辆向右转。

## 2. 架空轮方向检查

在车辆落地前依次执行，发现任一方向错误立即停止：

- [ ] 新逻辑左轮正命令：原右轮通道朝新车头方向转动；
- [ ] 新逻辑左轮负命令：原右轮通道朝新车尾方向转动；
- [ ] 新逻辑右轮正命令：原左轮通道朝新车头方向转动；
- [ ] 新逻辑右轮负命令：原左轮通道朝新车尾方向转动；
- [ ] 左右轮同时为正：车辆具备朝新车头直行的轮向；

## 4. LAB 阈值标定

当前起始阈值位于 `K230/red_line.py`：

```python
RED_THRESHOLDS = [(20, 100, 25, 127, 5, 127)]
```

标定步骤：

1. 固定相机位置、俯角和焦距，预热 2～3 秒；
2. 分别采样红色胶带、白色地面和黑色墙线；
3. 调整 LAB 阈值，使五个跟踪 ROI 中只保留红线；
4. 在直线、T 字、十字区域分别检查连通域；
5. 若单组阈值无法覆盖所有光照，可增加第二组红色 LAB 阈值，但必须重新测试误报；
6. 保存每种光照的质量、丢线和路口识别数据。

## 5. 中心和角度零点

车辆在直线中心静止时：

- [ ] `error_x` 稳定在 ±5 px 内；
- [ ] `angle_d10` 稳定在 ±20，即 ±2°内；
- [ ] `quality` 稳定高于 45；
- [ ] `direction_mask` 为 `0x02`；
- [ ] 图像右移红线后 `error_x` 为正；
- [ ] 红线朝右前方倾斜后 `angle_d10` 为正。

若静态中心存在固定偏差，优先调整相机安装；无法机械修正时再修改 `IMAGE_CENTER_X`。

## 6. 直线和路口识别

### 直线

- [ ] 连续通过直线 20 次，侧向分支误报为 0；
- [ ] 短时遮挡后可以恢复中心线；
- [ ] 黑色墙线不会被识别为红线；
- [ ] 质量不足时最多低速搜索约 100 ms，随后停车。

### T 字路口

- [ ] 左右分支连续两帧确认后进入减速；
- [ ] 无前向红线时输出 `0x05`；
- [ ] 减速发生在车辆进入路口中心之前；
- [ ] 离开路口后保持减速至少 300 ms。

### 十字路口

- [ ] 稳定输出 `0x07`；
- [ ] 连续三个普通直线帧后才退出路口减速；
- [ ] 路口横线不会把中心拟合突然拉向左侧或右侧。

## 7. MSPM0 安全验证

- [ ] 模式 7 启动后，第一帧有效红线不会立即驱动车轮；
- [ ] 连续两帧有效且质量合格后才启动；
- [ ] 停止 K230 发送后，在约 220 ms 内主动制动；
- [ ] 超时期间即使存在旧误差也不会继续运动；
- [ ] 恢复单帧不会启动，连续两帧才恢复；
- [ ] `L,0,0,0,quality,0` 触发丢线流程而不是通信超时流程；
- [ ] `T/N` 靶标帧不会刷新红线 freshness；
- [ ] `L` 红线帧不会刷新靶标 freshness。
